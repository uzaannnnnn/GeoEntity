## 4. Credentials and CLI

The operator CLI supports:

```text
geoentity device provision <entity-id> <label> [expected-interval-seconds]
geoentity device list
geoentity device rotate <device-id>
geoentity device revoke <device-id>
geoentity device detach <device-id>
geoentity device reassociate <device-id> <entity-id>
```

Provision/rotation/reassociation create 32 random bytes with `crypto/rand`; the CLI prints the bearer once. Only SHA-256 hashes are stored. Authentication strictly parses the bearer and uses constant-time hash comparison. Device lifecycle writes acquire the exclusive maintenance lock and insert actor-attributed audit events in their transaction. Listing omits credential IDs, hashes, and secrets.

## 5. Ingestion, idempotency, and entity lifecycle

The device route accepts one strict JSON observation with a 16 KiB cap, visible ASCII idempotency key, sensor ID grammar `[a-z][a-z0-9_]{0,63}`, finite values bounded to ±1e100, the planned unit allowlist, RFC3339 timestamp normalized to UTC, maximum five-minute future skew, maximum 90-day age, and optional ≤1 KiB bounded metadata object. Client-supplied entity/device/receive/actor fields are rejected as unknown fields.

The short SQLite transaction rechecks the exact authenticated credential ID, device/entity association and active states. It registers the unit once, compares a canonical SHA-256 payload digest for retries, inserts the observation and updates last-seen/credential-use timestamps atomically. Exact retries return the original observation; a different payload with the same key returns 409. Database uniqueness arbitrates duplicate keys, and SQL triggers reject invalid entity/credential/unit scope and all observation updates/deletes.

Deleting an entity revokes active credentials, detaches devices, records lifecycle audits, and deletes the entity in the existing transaction. Observation snapshots and device tombstones remain. Inactive and maintenance entities reject ingestion without silently revoking their credentials.

## 6. APIs and authorization

- `POST /api/device/v1/observations`: device bearer only; 201 first insert, 200 exact retry, generic 401 credential failure, stable validation/conflict/rate-limit errors.
- `GET /api/admin/devices`: admin-session protected, bounded ID-keyset listing without credential material.
- `GET /api/monitoring/latest?entity_id=...`: admin-session protected latest row per sensor, bounded and keyset paginated.
- `GET /api/entities/{id}/sensors/observations`: admin-session protected, bounded history with sensor filter, default 24-hour window, maximum 31-day explicit range, stable keyset cursor bound to entity/time/sensor filters.

V2.6 session, CSRF, and Origin checks remain in the outer middleware for every route other than the exact device ingest path and existing public auth/health routes. Tests cover device-to-admin denial, admin-cookie-only device denial, and unknown-path default-deny.

The view uses tables and no chart dependency. No credentials enter frontend state or storage.

The frontend API client tests, server-rendered empty-state component test, and freshness threshold test were added. Browser interaction, accessibility, and responsive viewport QA remain for V2.7C.

## 8. Backup and rollback

New backups declare schema version 7. Verification validates an exact known migration prefix and supports schema-6 and schema-7 manifests. Temporary schema-6 backup verification and restore are covered; opening the restored file through the V2.7 repository applies migration 007. Rollback to a V2.6 binary after migration 007 is unsupported unless a verified pre-007 backup is restored before telemetry writes. After telemetry writes, the safe path is roll-forward. No destructive down migration exists.

## 12. Deviations and known limitations

- No new dependencies were added. Browser-driven UI coverage was not run because the repository has no browser/component DOM test harness; the component test uses React server rendering and unit state helpers.
- Rate limiting is process-local and only supported with the exclusive per-database API lock. Trusted proxy CIDRs control whether `X-Real-IP` is honored. No multi-process or multi-host enforcement is claimed.
- Telemetry retention is indefinite and append-only. Database and backup sizes will grow with ingestion; no pruning or archive feature was added.
- The allowed sensor unit list is intentionally small, and a sensor's unit cannot change; changing units requires a new sensor ID.
- No threshold alerting, simulator, batch ingestion, or queue was added. No V2.7C independent QA or V2.7D Git review was performed.
