### Migration 005 and lifecycle semantics

Migration 005 adds only `entity_geofence_memberships`, `geofence_events`, their indexes, and append-only event triggers. Membership rows have a unique `(entity_id, geofence_id)` key and reference live entities/geofences with `ON DELETE CASCADE`; this deletes derived current state when either definition is deleted. Event rows deliberately have no entity/geofence foreign keys and snapshot both names, both IDs, transition type, evaluated coordinates, UTC time, and source, so deletion cannot erase history. The event table rejects `UPDATE` and `DELETE`.

Indexes support membership lookup by geofence/state/entity, geofence event history ordered by `(occurred_at DESC,id DESC)`, and entity event history ordered by the same keys. The implemented event endpoint uses the geofence history index; its optional entity/time filters further narrow that query. Membership reads use the `(entity_id,geofence_id)` primary key.

Membership states are `inside`, `outside`, or `inactive`. Entity creation and V2.4 CSV/GeoJSON import silently establish baselines for enabled definitions. Geofence creation and enabled definition edits silently calculate current membership for existing entities. Disable marks existing rows inactive and emits no synthetic exits; re-enable recalculates silently. Entity coordinate changes evaluate enabled definitions and emit only actual state transitions. Identical coordinates and unrelated field edits produce no transition. Entity/geofence deletion removes current membership but preserves event snapshots. On startup, missing baselines for entities and enabled definitions from a pre-005 V2.5B database are filled transactionally without events; existing membership rows are not rewritten.

### Transaction, idempotency, and concurrency

Entity updates read the current entity and membership states and evaluate the new coordinate inside the repository transaction before writing the entity. The transaction then updates the entity, upserts memberships, appends any transition rows, and appends the existing entity activity record before commit. Any failed write rolls all of those records back. Entity creation/import, geofence lifecycle recalculation, and delete cascades also use transaction boundaries.

The repository's existing single SQLite connection serializes in-process transactions. State comparison uses the persisted membership row inside that transaction; unique membership keys and identical-coordinate checks make duplicate retries idempotent. Event occurrence time is assigned in the transaction and serialized as fixed-width UTC text for correct SQLite ordering/cursors; it advances by one nanosecond if the wall clock does not advance past the previous event for that geofence. Concurrent identical/conflicting coordinates and concurrent definition/coordinate updates are covered by repository tests. No cross-process retry/locking layer was added; SQLite busy errors remain request failures if a separate process writes the same file concurrently.

### Geometry contract implemented

- Entity API remains latitude/longitude; geometry positions are [longitude, latitude].
- Circle center uses GeoJSON order; circle radius is finite, strictly positive, and capped at 10,000,000 metres. Containment uses Haversine distance with mean Earth radius 6,371,008.8 metres; the boundary is inclusive with 1 cm numeric tolerance.
- Polygon is one closed exterior ring; holes and MultiPolygon are rejected. The ring is normalized to counter-clockwise order. Vertex-to-vertex edges use minor great-circle arcs; containment and self-intersection checks use spherical vectors.
- Polygon antimeridian handling is explicit: reject any edge with a longitude jump over 180 degrees or a ring whose longitude span is 180 degrees or more.
- Polygon boundary points count as inside. Maximum exterior-ring size is 256 vertices. Coordinates must be finite WGS84 values. Degenerate, repeated-vertex, self-intersecting/touching rings and malformed positions are rejected.
- Geofence names are trimmed, 1–100 Unicode code points, unique by Go Unicode lowercase normalization. Geometry JSON is capped at 64 KiB; request body at 1 MiB.
- These were V2.5B implementation decisions where the plan deferred numeric limits or exact normalization. A maximum of 100 enabled definitions is enforced transactionally by create/update, with `409 GEOFENCE_LIMIT` on overflow. V2.5C's full membership/write-path measurement is recorded above; the geometry benchmark is not a claim of SQLite transaction throughput. Initial membership was delivered in V2.5C.

The dependency evaluation did not select a package. The official orb README describes 2D/planar geometry and separate geography helpers; its MIT license is compatible, but its documented planar operations do not establish this phase's spherical containment semantics. Its issue tracker also has open point-in-polygon reports. A bounded pure-Go implementation was used instead. No go.mod/go.sum changes were made.

### Migration and API

Migration 004, backend/internal/repository/migrations/004_geofences.sql, creates only:

- geofences: ID, display and normalized unique name, enabled flag, geometry type/canonical JSON, created/updated timestamps.
- index idx_geofences_enabled_created_at_id for enabled-filtered deterministic listing.

It creates no entity membership, geofence event, or entity FK. Migration tests apply it to fresh and populated prior-schema temporary databases, verify entity row preservation, ledger rerun, index presence, and injected failure rollback.

Additive endpoints:

| Method/path | Contract |
|---|---|
| GET /api/geofences?enabled=true|false&limit=&cursor= | Paginated list; limit defaults to 50 and maxes at 100; cursor is bound to the enabled filter and created_at/id ordering. Response has data and meta.limit/next_cursor. |
| POST /api/geofences | Strict JSON {name,enabled,geometry}; creates server UUID/timestamps; 201 data envelope. |
| GET /api/geofences/{id} | 200 data envelope; malformed UUID is 400 INVALID_ID; absent definition is 404 NOT_FOUND. |
| PUT /api/geofences/{id} | Full replacement of name/enabled/geometry; retains ID/created_at and changes updated_at; 200 data envelope. |
| DELETE /api/geofences/{id} | 204 empty body; absent definition is 404. |

Duplicate normalized names return 409 CONFLICT. Enabling a 101st definition returns 409 GEOFENCE_LIMIT. Invalid input returns 400 with the existing error envelope. Unknown fields are rejected. Existing V1 entity CRUD and V2.4 routes are unchanged; regression tests confirm the V1 list shape remains intact.
