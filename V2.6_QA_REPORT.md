## 3. Source Review Summary

An independent static code review was conducted prior to running dynamic tests:

1. **Authentication & Password Handling (`backend/internal/auth/auth.go`):**
   - Singleton admin model enforced by SQLite constraint `CHECK(id = 1)`.
   - Passphrase normalized with `norm.NFC.String()`; minimum 15 Unicode code points verified (`len([]rune(n)) >= 15`).
   - Argon2id verifier generated with `m=19 MiB, t=2, p=1`, 16-byte random salt, and 32-byte key. Formatted as standard PHC string.
   - Plaintext password never persisted, logged, or retained in memory structures.
   - Constant-time verification implemented via `subtleEqual`.
   - KDF work bounded by a buffered channel semaphore (`make(chan struct{}, 1)`), preventing memory exhaustion under concurrency.
2. **Session Management (`backend/internal/auth/auth.go`):**
   - 32-byte cryptographically random token (`crypto/rand`).
   - Database stores only SHA-256 hash (`digest(token)`).
   - Session fixation mitigated by rotating token on login (`Login` deletes prior token and issues fresh secret).
   - Expiry strictly enforced server-side: 30-minute idle timeout (`IdleTimeout`) and 12-hour absolute timeout (`AbsoluteTimeout`).
   - Cookie properties: `HttpOnly: true`, `Secure: true` (or dev override on loopback), `SameSite: Lax`, `Path: /`, no `Domain`, prefix `__Host-geoentity_session`.
3. **Middleware & Route Authorization (`backend/internal/auth/auth.go`, `cmd/api/main.go`):**
   - Single composition wrapper: `authService.Middleware(handler.New(store, logger))`.
   - Default-deny policy: Every `/api/*` path requires a valid session except `/api/health`, `/api/auth/login`, and `/api/auth/session`.
4. **CSRF & Origin Verification (`backend/internal/auth/auth.go`):**
   - Unsafe HTTP methods (`POST`, `PUT`, `PATCH`, `DELETE`) require `X-CSRF-Token` matching the session's SHA-256 hash.
   - Strict origin validation: Request `Origin` (or parsed `Referer` fallback) must exactly match configured `PublicOrigin`.
   - Wildcard CORS is disabled; headers are not exposed cross-origin.
5. **Rate Limiting & Proxy Parsing (`backend/internal/auth/auth.go`):**
   - In-memory `loginLimiter` capped at 4,096 buckets; entries idle > 10 minutes pruned. Fails closed when capacity is reached.
   - `clientIP` extracts IP from `RemoteAddr`; `X-Real-IP` trusted ONLY if direct peer IP is in `TrustedProxyCIDRs`.
6. **Audit Atomicity & Schema Migration 006 (`backend/internal/repository/migrations/006_admin_security.sql`):**
   - `admin_audit_events` created with append-only SQLite triggers (`admin_audit_events_no_update`, `admin_audit_events_no_delete`).
   - Audit inserts share the caller's SQL transaction via `auth.AuditTx`. Failure aborts the entire transaction.
7. **SQLite Online Backup & Restore (`backend/internal/backup/backup.go`):**
   - Uses driver API (`conn.Raw` -> `driver.NewBackup` / `driver.NewRestore`) rather than raw filesystem copy.
   - Validates integrity (`PRAGMA integrity_check == 'ok'`), foreign keys (`PRAGMA foreign_key_check` returns 0 rows), migration ledger continuity, and trigger existence before publishing manifests or restoring candidates.
   - Restore is strictly offline, enforces Unix `flock` maintenance lock, revokes active web sessions, and retains rollback snapshots.

1. **State Bounding & Memory Cap:**
   - Limiter capacity tested at limit 8 buckets. Adding 8th bucket succeeded; 9th novel IP failed closed (`allow() == false`).
   - Pruning verified: buckets untouched > 10 minutes are deleted.
2. **KDF Concurrency Limit:**
   - Evaluated via `s.kdf` channel (buffer 1). Concurrent login requests during active Argon2id hashing receive immediate `ErrRateLimited` without CPU/RAM explosion.
3. **Threshold Tests:**
   - Login rate limit: 10 attempts/IP/minute, 120 global/minute.
   - Mutation rate limit: 60 writes/IP/minute, 600 global/minute.
   - Import/export rate limit: 5 requests/IP/minute, 50 global/minute.
4. **Proxy Forwarding Header Spoofing:**
   - When request peer is `192.0.2.8:4567` (untrusted), `X-Real-IP: 203.0.113.9` is ignored; IP resolves to `192.0.2.8`.
   - When request peer is `10.0.0.2:4567` (matching `10.0.0.0/8` in `TrustedProxyCIDRs`), `X-Real-IP: 203.0.113.9` is parsed and trusted.

## 15. Known Limitations

1. **Single Administrator Model:** GeoEntity V2.6 is intentionally single-tenant and single-admin. Role-based access control (RBAC), multi-user hierarchies, and public user registration are explicitly out of scope.
2. **Process-Local Throttles:** Rate limiters reset on API restart and do not coordinate across multiple operating system processes.
3. **Operator-Managed Recovery:** Backup scheduling, remote off-site replication, and restore operations require manual operator execution via the `geoentity admin` CLI.
4. **Maintenance Lock Compatibility:** Exclusive database locks rely on POSIX file locking (`flock`).
