# GeoEntity V2.6 Security Operations

## First administrator

Build/run the CLI from `backend/` so its default database path matches the API:

```sh
go run ./cmd/geoentity admin provision
```

The CLI requires an interactive terminal, reads the passphrase without echo, confirms it, and accepts a minimum of 15 Unicode code points after NFC normalization. There is no default credential or public registration. To rotate a lost or compromised credential, stop the API and run `go run ./cmd/geoentity admin reset-password`; this revokes all current browser sessions.

## Browser origin and network bind

The API defaults to `127.0.0.1:8080` and refuses to start until an administrator exists. Set `GEOENTITY_PUBLIC_ORIGIN` to the exact browser origin. For the local Vite server (`http://localhost:5173`), use:

```sh
GEOENTITY_PUBLIC_ORIGIN=http://localhost:5173
GEOENTITY_DEV_COOKIE_INSECURE=true
```

The insecure cookie option is accepted only when the API bind address is an IP loopback address. Production uses HTTPS, the `__Host-geoentity_session` Secure/HttpOnly/SameSite=Lax cookie, and a TLS-terminating reverse proxy. Bind externally only by explicitly setting `GEOENTITY_ADDR` and `GEOENTITY_TRUSTED_PROXY_CIDRS`; the proxy must overwrite `X-Real-IP`. Other forwarding headers are ignored. The API does not enable CORS.

Sessions expire after 30 minutes idle or 12 hours absolute. Login rotates the cookie token; logout and password reset revoke sessions. Browser CSRF tokens remain in JavaScript memory and are sent on unsafe API requests. Unsafe requests require a matching Origin or Referer.

## Backups and restore

The CLI exposes verified, operator-run backups; it does not schedule backups:

```sh
go run ./cmd/geoentity admin backup create
go run ./cmd/geoentity admin backup list
go run ./cmd/geoentity admin backup verify ./backups/<name>.sqlite.manifest.json
```

`GEOENTITY_BACKUP_DIR` defaults to `./backups`; `GEOENTITY_BACKUP_KEEP` defaults to 10 verified snapshots. The backup directory is mode 0700 and snapshots/manifests are mode 0600. Snapshots use the SQLite Online Backup API, including with WAL enabled, and are checked for SHA-256/size, `integrity_check`, foreign keys, migration checksums, and required immutable triggers. A backup request is recorded in the admin audit trail. Store a separate copy off-device when required by the operator's recovery policy.

Restore requires the API to be stopped. The CLI obtains an exclusive database lock, verifies the manifest and snapshot, creates and checks a staged candidate, revokes sessions in that candidate, and records `database.restored` before swapping. A verified online rollback snapshot is retained as `<database>.rollback-<timestamp>.sqlite`; the prior database and any WAL sidecars are restored if the install step fails. Verify application data after recovery before removing rollback snapshots. Never use file copying to snapshot a live database.

## Audit and history

Admin mutations and audit inserts share their business transaction; an audit failure rolls back the mutation. `/api/admin/audit` provides bounded keyset pagination. Audit rows are append-only, actor snapshots have no cascading admin foreign key, and details exclude credentials, session/CSRF tokens, and imported record contents. Existing V2.3 system activity and V2.5 immutable geofence event rows are unchanged. Geofence history has no automatic retention or pruning.

## V2.6B limits

V2.6C passed its independent review and local browser walkthrough; production deployment readiness remains subject to operational verification. The password blocklist is an in-code curated set, not a continuously updated breached-password service. Login throttling is process-local for IP/global limits and persistent per administrator for account backoff; a multi-process deployment is outside this architecture. Synchronous geofence benchmarks are synthetic and single-process; they do not establish production SLOs. Verify the composed router, HTTPS proxy behavior, off-device recovery, and target-host tuning before public exposure.
