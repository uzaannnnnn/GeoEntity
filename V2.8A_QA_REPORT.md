## 4. Integration, authentication, and security results

The passing Go regression suites include composed production-auth flow, invalid login/session and logout invalidation, CSRF/Origin checks, default-deny protected routes, V1 entity CRUD/persistence, V2.5 geofence API compatibility, and device-route separation. Monitoring tests cover device credential hash storage and authentication, rejection of changed credentials, credential rotation/revocation/reassociation, entity-scoped ingestion, payload/timestamp/identifier validation, exact idempotent retries, conflicting retries, immutable sensor units, latest readings, history pagination, and trusted-proxy handling.

Repository lifecycle tests cover deleting an entity with active, revoked, and previously detached-associated devices; revoking outstanding credentials; preserving revocation timestamps and observation snapshots; foreign-key integrity; audit writes; and transactional rollback on an injected failure. Test and source review found no API response field exposing a raw device credential or credential hash. Requests and page sizes are bounded in the handler; history windows are bounded to 31 days, and SQL values are parameterized.

No new P0, P1, or P2 finding was reproduced in this QA scope. The previously reported V2.7C findings remain documented historically and their later remediation/re-test evidence remains intact. Remaining unexercised cases include two-process lock startup/recovery, multi-host rate limiting, some adversarial timestamp/metadata boundary combinations, conflicting concurrent idempotency keys, and a forced ingest rollback after initial sensor registration.

## 8. Performance and known limits

The lightweight `TestHistoryIndex` check passed for all-sensor and sensor-filtered cursor-page queries. A small existing handler integration test exercised paginated history. No large benchmark, soak, or production-capacity claim was made.

Known operating limits remain:

- SQLite uses a single writer and the supported API model is single-process. Rate-limit counters are process-local and do not provide multi-host enforcement.
- Telemetry is append-only with indefinite retention; database and backup size grows over time.
- Public deployment requires HTTPS and correct trusted-proxy CIDR configuration.
- The frontend bundle-size advisory remains. Large-scale behavior, soak behavior, and external deployment recovery have not been verified here.
- No browser screenshots were available from this QA run.
