## Main architectural decisions for implementation

1. Preserve V1 list and CRUD contracts exactly. Add `GET /api/entities/query` with keyset pagination and a deterministic `created_at,id` cursor.
2. Search only literal substrings in name/description; exact type/status filters. Use FTS5 trigram from additive migration 003 for queries of at least three code points and a documented short-query fallback. Parameterize all SQL. Do not search attributes/tags/categories.
3. Keep list pages independent from map data. Add bounded viewport `GET /api/entities/map` and all-filtered-results `GET /api/entities/map/extent`; without them the map would hide off-page entities or require the full dataset in the browser. Cap viewport results and reject overflow rather than silently rendering partial data.
4. CSV and GeoJSON export every matching record, never just the current list page. CSV carries metadata as deterministic JSON columns and has separate machine-readable and spreadsheet-safe modes. GeoJSON uses RFC 7946 Point coordinates `[longitude,latitude]`.
5. CSV/GeoJSON import is create-only, preview then confirm, all-or-nothing. Validate bounded input before the write transaction; recheck DB-dependent constraints inside it. Preserve ID or regenerate explicitly. Existing IDs and in-file duplicate IDs reject; normalized duplicate names are warnings, not uniqueness constraints. Unknown tags/categories are previewed and created atomically on confirmation.
6. Round-trip current and prior-type attributes, tags and categories. Never import prior activity. Each imported entity gets one allowed `entity.created` event with import source/format/batch context in the same transaction.
7. No new dependency, import-job table, service, database engine, or change to migrations 001/002. Migration 003 remains additive and immutable after application.

Exact routes, request/response examples, file schemas, duplicate policy, limits, risks and tests are in `V2.4_IMPLEMENTATION_CONTRACT.md`.

## Principal risks and implementation gates

- FTS5 trigram availability must be confirmed on every supported build/runtime; migration must fail safely and tests must cover a populated DB. The 1–2 character fallback may scan and has SQLite ASCII-only `lower()` behavior.
- V1 full-list clients remain unbounded by design. New frontend code must opt into the paged endpoint, so legacy API compatibility does not itself remove legacy scale limits.
- Map viewport cap may be reached in dense areas; show a clear zoom-in state. Global Fit All can span a very large extent. Antimeridian minimal bounds are not planned.
- Synchronous imports hold SQLite's single connection and can create many activity rows. Enforce strict size/row/time limits and benchmark 5,000 rows before enabling the maximum in UI.
- Preview fingerprint catches file mismatch but is not authentication. The API must not be exposed publicly without the later security phase.
- A standalone import does not preserve historical event streams or exact source audit actors. Import creates new system-attributed events at commit time.
- Spreadsheet-safe CSV intentionally changes dangerous text cells and cannot be used for byte-perfect round-trip.

### 3. Server-Side Search & Filter Semantics

- **Search Scope:** Matches literal substrings in `name` or `description` only. Does not match IDs, types, statuses, custom attributes, tags, or categories.
- **Query Normalization:** Trims leading/trailing whitespace, collapses internal Unicode whitespace runs to a single ASCII space, limits query to 128 Unicode code points (`utf8.RuneCountInString`).
- **>= 3 Code Points:** Executes FTS5 trigram match using `alias.rowid IN (SELECT rowid FROM entity_search WHERE entity_search MATCH ?)`. Quoting via `quoteFTSPhrase` wraps the query in double quotes and escapes embedded quotes (`""`), treating special FTS characters (`*`, `+`, `AND`, `OR`, `NOT`, `NEAR`, colons, parentheses) as literal characters.
- **1–2 Code Points:** Falls back to parameterized `(instr(lower(name), lower(?)) > 0 OR instr(lower(description), lower(?)) > 0)`. Documented known limitation: SQLite's `lower()` is ASCII-only.
- **Filter Composition:** `q`, `type`, and `status` combine with AND. Repeated query keys or unknown parameters are rejected with `400 INVALID_QUERY`.

### 4. Cursor Pagination Contract

- **Endpoint:** `GET /api/entities/query?q=&type=&status=&limit=&cursor=`
- **Ordering:** Deterministic `created_at ASC, id ASC` matching V1 order. Keyset continuation predicate: `(created_at > ?) OR (created_at = ? AND id > ?)`.
- **Page Limits:** Default 50; allowed range 1–100. Explicit 0 or >100 returns `400 INVALID_QUERY`.
- **Cursor Structure:** Base64URL-encoded versioned JSON:
  ```json
  {"v":1,"created_at":"2026-11-03T00:00:00.000000000Z","id":"uuid","filter_hash":"<sha256-hex>"}
  ```
  `filter_hash` is SHA-256 over canonical `{q, type, status, sort}`.
- **Validation:** Tampered cursors, malformed base64, JSON with unknown fields, invalid UUIDs, invalid timestamps, version mismatch, or filter mismatch return `400 INVALID_QUERY`.
- **End of Results:** On the final page or empty result, `next_cursor` is `""` (empty string, never null).
- **Response Format:**
  ```json
  {
    "data": [
      {
        "id": "uuid",
        "name": "Asset Alpha",
        "type": "vehicle",
        "description": "Depot unit",
        "status": "active",
        "latitude": -6.2,
        "longitude": 106.8,
        "created_at": "2026-11-03T00:00:00Z",
        "updated_at": "2026-11-03T00:00:00Z"
      }
    ],
    "meta": {
      "limit": 50,
      "next_cursor": "eyJ2Ijox...",
      "matching_count": 1,
      "status_counts": {
        "active": 1,
        "inactive": 0,
        "maintenance": 0
      }
    }
  }
  ```
- **Counts:** `matching_count` reflects the count matching `q`, `type`, and `status`. `status_counts` reflects the distribution across `active`, `inactive`, and `maintenance` under the current `q` and `type` (even when a status filter is applied).

### 5. Independent Map Dataset APIs

- **`GET /api/entities/map?west=&south=&east=&north=&q=&type=&status=`**
  - Returns lightweight marker points matching filters within the viewport:
    ```json
    {
      "data": [
        {"id": "uuid", "name": "Asset Alpha", "type": "vehicle", "status": "active", "latitude": -6.2, "longitude": 106.8}
      ]
    }
    ```
  - Independent of list page: moving between pages of `GET /api/entities/query` does not alter map marker results.
  - Result limit: maximum 5,000 features. If more match, returns `413 MAP_RESULT_LIMIT`: `"More than 5000 entities match this map view; zoom in to see markers"`.
  - Antimeridian support: when `west > east`, query handles dateline wrap seamlessly.
- **`GET /api/entities/map/extent?q=&type=&status=`**
  - Returns the bounding box and count of all matching valid coordinates across the entire dataset:
    ```json
    {
      "data": {
        "count": 42,
        "bounds": {"west": 106.7, "south": -6.4, "east": 106.9, "north": -6.2}
      }
    }
    ```
  - If count is 0, `bounds` is `null`.

### 1. Architecture & State Separation

V2.4C cleanly separates list presentation data from spatial map marker data:

1. **Independent Data Sources:**
   - **List Pipeline (`EntityList`):** Consumes `GET /api/entities/query?q=&type=&status=&limit=50&cursor=`. Keyset pagination manages incremental page appends via cursor continuation. Displays authoritative server metadata: `showing X of Y matching entities`, status breakdown counts, loading skeletons, and an explicit "All X matching entities loaded" terminal indicator.
   - **Map Pipeline (`MapView`):** Consumes `GET /api/entities/map?west=&south=&east=&north=&q=&type=&status=` returning lightweight `MapEntity` coordinates (`id, name, type, status, latitude, longitude`). Off-screen entities are omitted from the Leaflet marker cluster tree, protecting browser DOM and memory at scale.
   - **Extent Pipeline ("Fit All"):** Consumes `GET /api/entities/map/extent?q=&type=&status=`. Retrieves server-aggregated bounding box (`[west, south, east, north]`) and total matching count across all matching entities without loading records into browser memory.

2. **Controlled Filtering & Debounce:**
   - Search input uses a 300 ms debounce timer.
   - Quick "Clear Search" button (`X`) and "Reset Filters" action.
   - Changing filters resets list pagination back to page 1 while immediately refetching the map viewport with updated filter parameters.

3. **Off-Page Entity Selection:**
   - When a user clicks a map marker whose entity is not loaded on the active list page, `handleSelectMapMarker` performs an optimistic selection and asynchronously fetches the full entity record via `GET /api/entities/{id}`. The detail sidebar (Overview, Attributes, Tags & Categories, Activity Log) populates immediately.

4. **Map Viewport Listener & Overflow Handling:**
   - `MapViewportListener` debounces Leaflet `moveend` events (300 ms) and uses a coordinate delta threshold (0.0001°) to prevent re-requesting identical bounding boxes.
   - Handles antimeridian wrapping `[-180, 180]` and latitude clamping `[-85, 85]`.
   - When the backend returns HTTP 413 `MAP_RESULT_LIMIT` (>5,000 markers in view), the UI renders a non-disruptive map warning banner: *"More than 5,000 entities in this area. Zoom in to view markers."*
   - Request cancellation guards (`RequestGuard`) ensure late-arriving responses from superseded queries are discarded, preventing race conditions and infinite re-render loops.
