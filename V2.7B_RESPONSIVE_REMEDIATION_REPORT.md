## Defect reproduction and cause

Chrome for Testing `156.0.8078.4` reproduced the defect at 390×844. Before the fix, `.header-actions` measured 810.25 px wide and ended at x=1049.80. The header was a single, non-wrapping 60 px row. The separate fixed Sign out control occupied x=286.39–374, y=12–48 and overlapped the API Online badge at x=239.55–314.27. Header navigation extended beyond the right edge and was clipped by the viewport/container. The application container uses `overflow: hidden`, so document `scrollWidth` remained 390 px and did not reveal the overflowing descendants.

The before screenshot shows the reproduced state: [before_390x844.png](<[LOCAL_PATH_REDACTED]>).

## Changes

- `frontend/src/components/Header.tsx`: placed Sign out and its error feedback in the header alongside the other controls.
- `frontend/src/App.tsx`: passed the existing sign-out callback and error state into the authenticated header; authentication behavior is unchanged.
- `frontend/src/App.css`: changed the header to a three-column responsive grid at widths through 900 px, wrapped header actions, and compacted mobile spacing below 480 px. The desktop header remains a 60 px row; Sign out now participates in its flex layout instead of overlaying it.

No component geometry test framework is installed in the frontend. Since layout correctness depends on actual CSS layout, exact-size Chrome CDP assertions were used instead of adding a source-text or mocked DOM test.

## Browser evidence

The browser inspected the bounding rectangles of the header, API badge, Sign out, and every navigation button. It checked viewport visibility, center-point hit testing, overlap, and document `scrollWidth` against `clientWidth`.

|---|---:|---|---|---:|---|
| 390×844 | 140.5 px | None | All visible and center-hit-testable | 390 / 390 | Pass |
| 768×1024 | 148.6 px | None | All visible and center-hit-testable | 768 / 768 | Pass |

At 390×844, the API badge is at x=12–107.41, y=55.75–83.75; Sign out is at x=296.39–378, y=8–44. Navigation controls wrap to additional rows and remain inside the viewport. The Monitoring button opened the monitoring view, Back to map returned to the map, and Sign out returned to the unauthenticated screen. Chrome reported zero JavaScript exceptions and zero console errors. It emitted one verbose browser password-form accessibility recommendation during sign-in; this was not an application error.
