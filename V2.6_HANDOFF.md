## Decisions for V2.6

- One administrator only; no registration/default credentials. Provision and reset with an operator CLI that reads a password without echo. Require a 15-character Unicode-code-point passphrase minimum, consistent NFC normalization, a common/context/compromised password blocklist, and no composition rules or periodic forced rotation.
- Argon2id, salted/versioned verifier, initial OWASP minimum profile benchmarked on target host; cap concurrent KDF work. Store no plaintext password.
- 32-byte random opaque browser session; store only a hash in SQLite. `__Host-geoentity_session` cookie is Secure, HttpOnly, Path=/, SameSite=Lax, no Domain. Enforce 30-minute idle and 12-hour absolute expiry server-side; rotate on login/password change and revoke on logout/reset.
- Session-bound synchronizer CSRF token in memory and `X-CSRF-Token` on unsafe methods; exact trusted Origin/Referer validation for all unsafe browser requests, including login. CORS stays disabled. Never trust arbitrary forwarded headers.
- Default `GEOENTITY_ADDR` to loopback. Outside access requires explicit TLS proxy, `GEOENTITY_PUBLIC_ORIGIN`, optional trusted proxy CIDRs, network, and security configuration. Health remains minimal/public.
- Persist admin actions in a new append-only `admin_audit_events` snapshot table within the mutation transaction. Do not rewrite/upgrade actor identity on historical V2.3 or V2.5 events.
- SQLite Online Backup API snapshot with manifest/checksum, restricted permissions, integrity and foreign-key verification. Restore only offline from a validated staged copy; keep a rollback copy and revoke sessions in the restored DB.
- Retain geofence history indefinitely in V2.6. No pruning or trigger weakening. Profile synchronous geofence evaluation and optimize only when measured representative workload justifies it.
- V2.7 uses a separate entity-scoped device credential and telemetry path; no IoT implementation in V2.6.

Details and test matrix: [V2.6_TECHNICAL_PLAN.md](V2.6_TECHNICAL_PLAN.md).

## Migration and data rules

Migration 006 is additive. Proposed tables are a singleton `admin_users`, `web_sessions` storing only session/CSRF hashes, and `admin_audit_events` containing actor/resource snapshots and redacted payloads. Audit rows must have no FK that would cascade history away and must reject UPDATE/DELETE. Do not alter `activity_events` actor constraint or backfill historic actors. Do not alter immutable `geofence_events`. Verify checksum preservation and upgrades on temporary V2.5 copies only.

Backup/restore must use the SQLite Online Backup API or a separately proven consistent method, not a raw copy of a live database. Verify checksum, `integrity_check`, `foreign_key_check`, migration ledger and selected application invariants. Restore only with the service stopped and a separately preserved rollback copy. Never invoke migration/backfill startup paths merely to verify a backup.
